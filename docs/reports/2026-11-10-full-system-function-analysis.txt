Van de can sua o cap catalog:
1. `work_order:assign` va `work_order:manage` dang phan bo chua phan biet
   schedule/assign/cancel. Can tach action neu Dispatcher tiep tuc ton tai.
2. `service_request:comment_internal` tren Technician/Dispatcher can dinh nghia
   ro: chi doc, ghi hay ca hai; doi tuong nao; khong de role thay noi dung
   sensitive cua customer.
3. `customer:manage` va `equipment:manage` cua Service Manager can co branch
   scope/server check, khong chi dropdown UI.
4. `cost_estimate:respond` va `equipment_handover:respond` phai luu
   actor/customer/revision/snapshot/reason; khong chi luu status.
5. Tat ca role nhieu role van phai bi gioi han boi data scope; role union
   khong duoc tu dong lam rong branch/customer scope.

7. KIEN TRUC THAY THE DE XUAT
------------------------------

7.1 Mot state machine chung cho moi aggregate

Moi aggregate dung command thay vi update tu do:

  Service Request:
    NEW -> AWAITING_INFO -> UNDER_REVIEW -> ACCEPTED/REJECTED/CANCELLED
    ACCEPTED -> AWAITING_CUSTOMER_APPROVAL (neu ngoai warranty)
    ACCEPTED -> READY_FOR_WO -> PROCESSING -> RESOLVED/PARTIALLY_RESOLVED/UNRESOLVED

  Work Order:
    CREATED -> ASSIGNED -> ACCEPTED -> IN_PROGRESS -> ON_HOLD
    ON_HOLD -> IN_PROGRESS
    IN_PROGRESS -> COMPLETED/CANCELLED
    COMPLETED co technicalResult rieng; customerAcknowledgement la luong rieng.

  Handover:
    DRAFT -> PENDING_CUSTOMER_CONFIRMATION -> ACCEPTED/REJECTED/EXPIRED

  Inventory operation:
    PREPARED -> PENDING -> SUCCEEDED/FAILED/UNCERTAIN -> RECONCILED

Khong cho client tu dat status. Moi command tra:
  { resource, previousState, newState, allowedActions, receipt, correlationId }

7.2 Data scope mot cach nhat quan

  request context -> tenantId -> customerId (neu customer) -> branchId
  -> resource owner/snapshot -> permission -> allowed action.

Tat ca read/list/detail/mutation/download/notification/count deu dung cung
scope helper. Branch routing chi quyet dinh owner luc tao; sau do snapshot
branch tren SR/WO/stock operation.

7.3 Mot UI shell theo next action

Moi role co:
  - Context bar: tenant, branch/customer scope, environment, timezone.
  - Work queue: viec can xu ly, viec dang cho ai, han tiep theo.
  - Detail: source chain, actor, status, allowedActions.
  - Evidence: history, files, audit, correlation.
  - Recovery: retry/inspect/abort khi uncertain.

Khong tao 8 ban sao cua cung mot detail. Dung component chung va policy
`allowedActions` tu server.

7.4 Mot transaction/operation receipt cho thao tac nguy hiem

Ap dung cho estimate, handover, WO assignment, inventory issue/return,
attachment finalize va report submit:
  - client gui idempotencyKey;
  - server luu receipt;
  - timeout tra `UNCERTAIN`, khong tu dong gui lai;
  - client co "Kiem tra ket qua";
  - reconciliation co the doi soat theo correlationId.

11. KET LUAN CUOI
-----------------

He thong da co nen tang tot cho MVP: microservice ownership, RBAC catalog,
tenant/customer scope, equipment dossier, service request, work order,
maintenance, inventory ledger, notification projection va role workspace.

Nhung diem khong hop ly lon nhat khong nam o viec "thieu them nhieu man hinh",
ma nam o:
  1. chua chot ownership giua Service Manager va Dispatcher;
  2. UI co the khong giai thich branch/customer scope;
  3. approval/revision/acknowledgement chua tach khoi completion;
  4. thao tac multi-service va kho can receipt/recovery/idempotency;
  5. mobile va attachment can xu ly uncertain state;
  6. acceptance test chua co ket qua baseline, khong duoc suy ra PASS tu build.

Phuong an thay the khuyen nghi la "giu kien truc, thay cac diem mo ho bang
command/state/receipt/scope/audit", khong viet lai toan bo. Sau khi chot 10
quyet dinh o muc 10, uu tien P0 theo Phase 0-3, sau do moi polish UI va
mo rong Mobile. Ket qua nghiem thu cuoi cung phai dua tren test plan ngay
10/11/2026 va co bang chung cho tung role, tung tenant, tung branch va tung
duong file/notification.
